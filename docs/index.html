Free, open-source terminal manager for Windows

Every project, server and Claude, one click away.

Shellman is a terminal manager for Windows 10 and 11. Save a folder with the command you run there, or a server. One click opens it in a tab or split. Each Claude keeps its own conversation, can get its own git worktree, and you read its changes right beside it.

01 · sessions

Saved terminal sessions for the places you work

A session is a folder and the command you run there, like claude, npm run dev or terraform plan. Or an SSH host. Click it for a tab, middle-click for a split.

  • Each session lists its open terminals, so the right one is a click away, even with twenty tabs.
  • Tabs, splits and folders come back when you start Shellman again.
  • Ctrl+Shift+P finds any session as you type.

02 · claude code

Several Claude Code sessions in one repository

Open in new worktree gives a terminal its own folder and branch, so two Claudes never edit the same files. It stays under its session in the sidebar, with its branch name.

  • Every Claude tab keeps its own conversation and gets it back after a restart.
  • The tab lights up when Claude finishes or needs you, and the taskbar flashes if Shellman is in the background.
  • Removing a worktree tells you first what would be lost.
  • Shift+Enter for new lines, Ctrl+V pastes screenshots.

Works with any command. Claude Code just gets a few extras.

03 · review

See what changed without opening an editor

Show files (Ctrl+Shift+G) opens the session's folder read-only: the tree, changed files marked, and each change as a diff with the changed words highlighted. It follows along while Claude edits, commits or switches branches.

  • Compare with the last commit, another branch or an earlier commit.
  • Ctrl+click a path in the terminal, like src/app.ts:42, to open it at that line.
  • Search all files, go to a definition, read Markdown as a preview.
  • Nothing is ever written. The VS Code button opens the folder when you want to edit.

04 · ssh

SSH and Telnet sessions with the keys you already have

Shellman runs Windows' own OpenSSH. Your key files, the Windows ssh-agent, 1Password's SSH agent and ~/.ssh/config work as they do anywhere else. Shellman never stores passwords or private keys.

  • Save hosts next to your folders, or type user@host to connect without saving.
  • Pick a key per host, so servers don't give up after six tries.
  • Old equipment that only speaks ssh-rsa or CBC? Allow old algorithms for that host.
  • Telnet too, with the Windows Telnet Client.

05 · api requests

API requests next to your terminals, shared through git

Link a group to a folder of request files your team keeps in git. Requests open in tabs and splits like terminals and run through Windows' own curl.

  • {{variables}} come from .env and environment files. Secrets stay in your own .env.local or come from 1Password (op://…).
  • Give a variable several values, each with a note on when to use it, and switch between them from a list.
  • Responses as folding JSON with headers, timing and cookies.
  • Git sync commits only Shellman's files and pulls your teammates' changes.
  • Import from Postman. Copy or paste curl commands.

Also included

  • PowerShell 7, Windows PowerShell, cmd, Git Bash and WSL, found automatically
  • Switch a running terminal to another shell
  • Session folders inside WSL, in any distribution
  • Notes for commands and log output (Ctrl+Shift+J), reopened after a restart even when never saved
  • Splits to any depth; move panes between tabs
  • New tabs and splits start in the current folder
  • Groups and colours for sessions
  • Notifications from bells and OSC 9/777
  • Warns before closing a running program
  • Six themes, GPU rendering, a 5 MB app written in Rust
  • Keyboard first, with no Ctrl+Alt, so AltGr keeps working. All shortcuts →

Questions

How is Shellman different from Windows Terminal?

Windows Terminal opens shells; Shellman opens the places you work. A saved session is a folder and the command you run there, or an SSH or Telnet host, and the sidebar lists the terminals open in each one. On top of that come git worktrees for Claude Code, a read-only view of the changes and API requests. Coming from XShell or MobaXterm? Your SSH hosts sit next to your folders, and XShell sessions can be imported.

Is Shellman free?

Yes. It is free and open source under the MIT license, with no account and no telemetry. On its own it only checks GitHub for updates, and you can turn that off. The code is on GitHub.

Does Shellman store my passwords or keys?

No. ssh asks for passwords in the terminal, and private keys stay in your key files, the Windows ssh-agent or 1Password. For a key you pick from an agent, Shellman keeps only its public half. API secrets stay in .env.local, which git ignores, or in 1Password, and reach curl through its environment, never a command line. Your sessions are saved on your own machine, in %APPDATA%\app.shellman.desktop.

Do I need Claude Code?

No. Shellman works with any shell or command. Claude Code gets a few extras: its own conversation in every terminal, git worktrees, notifications, Shift+Enter for new lines and pasting screenshots.

What do I need to run it?

Windows 10 or 11, 64-bit, with the WebView2 runtime. Windows 11 has it, and most Windows 10 PCs get it with Edge. It installs per user, without admin rights. SSH uses Windows' own OpenSSH client; the Files pane and worktrees use git; Telnet needs the optional Telnet Client feature.

How do updates work?

New versions download in the background and install the next time you start Shellman. Only updates signed with the project's key are accepted. In Settings you can switch to notifications only or turn checks off, and Settings → About lists what changed.

Why does Windows SmartScreen warn about the installer?

The installer is not signed with a paid code-signing certificate yet, so SmartScreen asks you to confirm. Choose More info, then Run anyway. The source code and the build workflow are on GitHub.
